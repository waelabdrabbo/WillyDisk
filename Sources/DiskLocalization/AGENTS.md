# DiskLocalization — agent notes

The one string catalog and the one lookup path for everything the app shows.

## Where things are

- `Localizable.xcstrings` — the catalog. Keys are the English source text; `%@` and
  `%lld` mark substitutions. It is excluded from the target's resources: SwiftPM's
  catalog path also asks the toolchain to derive Swift symbols, and a format-only key
  cannot be a symbol.
- `Resources/en.lproj`, `ar.lproj`, `en-XA.lproj` — the compiled tables SwiftPM ships.
  Generated by `bash Scripts/localize.sh`; `--check` fails when they are stale. They are
  committed because a build must not need `xcstringstool`.
- `BundledResources.swift` — where the resource bundle is found at run time:
  `Contents/Resources` first, then beside the binary, then where a test bundle keeps
  it. SwiftPM's `Bundle.module` never reaches `Contents/Resources`, so nothing loads
  resources through it; `docs/ARCHITECTURE.md` §5 has the reasoning.
- `L10n.swift` — `string(_:)`, `format(_:_:)`, language resolution, and the
  right-to-left answer. Foundation only: `DiskCLI` links this target and must
  never pull in AppKit or SwiftUI. It localizes through a language's `.lproj`, and
  reads the table file itself when Foundation will not serve that language.

## Rules

- Every user-visible literal in `Sources/DiskUI`, `Sources/WillyDiskApp`, and
  `Sources/DiskCLI` goes through `L10n`. A view calls
  `Text(L10n.string("…"))`; a count calls `L10n.format("%lld files", n)` and
  gets its plural from the catalog, never from `n == 1 ? … : …` in code.
- A plural phrase is one catalog entry with plural variations. Do not build a
  sentence around a hand-concatenated number and noun.
- Keep the same `%@`/`%lld` placeholders in every language, and do not add a
  literal `%` to a formatted string unless it is `%%`.
- English is the source language and the fallback. Arabic (`ar`) is the first
  finished translation; `en-XA` is the doubled-length pseudolanguage the render
  harness reviews truncation with, and it is generated, not written by hand.
- Update the catalog and the code in the same change, then run
  `bash Scripts/localize.sh`. The QA suite fails when a user-visible literal bypasses
  the catalog, when a key used in source is not in the catalog, when a catalog key has
  no call site, when a key has no Arabic value, or when a language's placeholders
  differ from English.
- A key reached through a variable (a preset's `name`, a category's display name) is
  still an English source string in the catalog; keep those names free of format
  placeholders.
- The app can pin one language from Settings (`AppLanguage` in DiskUI) and re-pin `L10n`
  while it runs; its System choice clears the override so the catalog follows macOS.
  The override changes WillyDisk's own windows and dates, not AppKit panels or the
  command line. A language's own name is a catalog key too, so the picker never needs a
  literal.

## Adding a string

1. Use the English sentence as the key, with `%@`/`%lld` in place of values.
2. Add `en`, `ar`, and `en-XA` localizations. For a count, add plural
   variations; Arabic carries zero, one, two, few, many, and other.
3. Call `L10n.string`/`L10n.format` from the view or support type.
4. Run `python3 Scripts/pseudolanguage.py` to regenerate `en-XA` from the English
   values, then `bash Scripts/localize.sh`; the guard test then proves the catalog, the
   source, and the compiled tables agree.
